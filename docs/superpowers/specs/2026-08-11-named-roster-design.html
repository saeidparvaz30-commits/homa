Homa v2: Named Session Roster

Windows tray monitor for Claude Code sessions

v1 tells you how many sessions want attention. v2 tells you which ones, by names you chose yourself, in a list that is always on screen.

Status: approved design Next: implementation plan Supersedes parts of 2026-07-24-homa-design

01Problem

Homa v1 shipped and has been running for roughly two weeks. Two things make it unhelpful in daily use.

Names are meaningless

Claude writes its own name into each session file, auto generated from the working directory plus a counter: agent-simorgh-61. Homa displays that verbatim (RosterView.tsx:23). Reading it does not tell you which session is which piece of work.

The surface you glance at carries no names at all

The always on top overlay is a count pill (OverlayPill.tsx:31). It says how many things want attention but not which, so every alert costs a context switch into the main window just to find out what fired.

02Goals

Chosen names

Every session shows a name you picked.

Typed once

A name persists across future sessions without retyping.

Zero clicks

The named list is visible without opening anything.

Fewer false alarms

Shell activity stops reading as "needs you".

Non goals

  • Writing anything into ~/.claude. Homa stays strictly read only against Claude's files; names live in Homa's own store.
  • Reworking the main window or the Tamagotchi view. They inherit names for free.
  • Changing toast, sound, or tray colour logic.

03Alias store

New module src-tauri/src/alias.rs, backed by %APPDATA%\homa\aliases.json.

{
  "c:\\users\\saeid\\desktop\\migration site": "migration site",
  "c:\\users\\saeid\\desktop\\claude projects\\homa": "homa"
}
Scope: the working directory, not the session. A session ID is created fresh on every run, so a session scoped name would have to be retyped daily. A cwd scoped name is typed once and every future session in that folder inherits it. This is the decision that makes renaming worth building at all.
ConcernDecision
Key normalisationLowercase, separators normalised, trailing separator stripped. Windows path comparison is case insensitive and the same folder arrives spelled differently depending on how the session started.
CollisionsTwo live sessions in one folder resolve to the same alias. Display appends #1, #2 ordered by started_at ascending, so numbering stays stable rather than flipping between polls.
WritesAtomic: serialise to a temp file in the same directory, then rename over the target. Rewritten whole on each change.
FailureMalformed or missing file loads as an empty map rather than failing, matching how settings.rs already degrades.

Resolution order

Applied in the enrichment step, so overlay, main window, and toast text all see the same name.

  • Alias for the session's cwd, plus collision suffix if needed
  • Otherwise Claude's session.name
  • Otherwise the last path segment of cwd

Commands exposed to the frontend

  • set_alias(cwd, name) — trims input; an empty or whitespace only name removes the entry rather than storing a blank
  • get_aliases()

04Overlay becomes the roster

OverlayPill.tsx is replaced by OverlayRoster.tsx.

AspectBehaviour
VisibilityAlways on. overlay::drive no longer shows and hides on attention state. Shown once at startup and stays up. Attention is signalled by dot colour plus the existing toast, sound, and tray colour, all unchanged. The list is a dashboard; the alerts remain alerts.
LayoutOne row per live session: status dot, then name. Sorted by status priority descending (waiting, idle, working, ended), then by name for a stable order inside a group.
DataThe overlay currently receives only the tray-summary count event. The full AgentState list must be emitted to it too. The main window already consumes this via useAgents.
SizingHeight set from row count on each update, clamped to a maximum after which the list scrolls, so a burst of sessions cannot grow it to fill the screen. Fixed width.
PositionDragged position persisted to settings, restored at startup. An always visible window that resets position every launch would be worse than the pill it replaces.
FocusShown without stealing focus. Must not appear in the taskbar or alt tab. Clickable for renaming, never interrupting a game or terminal.
Ended sessionsStay as a grey row for roughly 10 seconds after the process dies, then disappear. Long enough to notice an exit, short enough that the list does not accumulate corpses.
Empty stateWith no live sessions the overlay collapses to a single muted "no sessions" row. It does not hide. Hiding on empty would mean the window vanishes and reappears through the day, which is the behaviour this design removes, and would leave nothing to drag when repositioning.

Colour vocabulary (unchanged from v1)

  • waiting on you
  • idle, finished its turn
  • working, the calm state
  • ended

05Rename in place

Double click a row. The name becomes a text input seeded with the current value and selected. Enter commits, Escape cancels, blur commits. An empty value clears the alias and the row falls back to Claude's name on the next poll.

Enter saves · Esc cancels · empty resets

Committing calls set_alias with the row's cwd. Because the store is cwd keyed, renaming one row immediately renames every other live session in the same folder. This is intended, and the collision suffixes make the result readable.

06Status mapping fix

shell maps to Working.

It appears in the observed status log interleaved with busy and idle, and corresponds to the session running a shell command, which is work in progress rather than a finished turn. Mapping it to Working removes a recurring false attention signal.

The unknown status fallback stays as it is. Failing toward attention is still right for a value nobody has seen yet; the fix is that shell is no longer unknown. probe.rs keeps logging distinct raw statuses so the next unseen value is caught the same way this one was.

07Testing

Rust

  • Alias key normalisation across case and separator variants
  • Name resolution precedence including the full fallback chain
  • Collision suffixing, and its stability across repeated resolution
  • Atomic write followed by read back
  • Corrupt and absent alias files loading as empty
  • map_status("shell", true) returning Working, alongside existing mapper tests

Frontend

  • Roster rows render in priority order
  • Double click enters edit mode
  • Enter commits and invokes the command with the row's cwd
  • Escape cancels without invoking
  • An empty commit clears rather than storing blank

Manual

The part that cannot be asserted: overlay stays up across status changes, does not steal focus, does not appear in alt tab, sizes correctly from one row to many, and restores its position after a restart. This is what v1 never got, and it is where the real verdict on v2 lives.

08Risks

RiskMitigation
Always visible costs screen space permanentlyFixed narrow width, auto height, remembered position. If it proves intrusive while gaming, the fallback is the collapse to a thin bar variant, which was considered and set aside. Nothing here blocks adding it later.
The shell reading could be wrongIf shell means blocked on a shell command needing input, Working would hide a real attention state. The observed status log will show it, and the change is one line in WAITING_STATUSES.
Renaming affects sibling sessionsBy design, but surprising the first time two sessions in one repo rename together. The #1 and #2 suffixes are what make it legible.
