Homa v2: Named Roster

Eight TDD tasks. Rust first (store, resolution, lifecycle, wiring), then the overlay UI, then the always visible window behaviour that has to be checked by eye.

8 tasks No new dependencies Commit per task Spec: 2026-08-11-named-roster-design

01Architecture

A new alias.rs owns a cwd keyed name store in %APPDATA%\homa\aliases.json. The poller applies aliases to AgentState.name during each scan, so every existing consumer (overlay, main window, toast text, sort order) inherits chosen names with no changes of its own. The overlay swaps its count pill for a roster component that renders one row per session, self sizes its window height to the row count, and writes names back through two new Tauri commands.

One thing the spec assumed that turned out to be free. The spec said the full agent list "must be emitted to the overlay too". It already is: Tauri v2's app.emit broadcasts to every webview, so agents-updated reaches the overlay window today. The overlay just has to listen. No Rust plumbing needed.

Global constraints

  • No new dependencies, Rust or npm. If a task appears to need one, stop and ask.
  • Homa never writes into ~/.claude. All Homa state lives in %APPDATA%\homa\.
  • cargo is not on PATH by default: prepend $env:USERPROFILE\.cargo\bin.
  • Rust tests from src-tauri/ with cargo test; frontend from the root with npm test.
  • No em dashes in any string, comment, commit message, or doc.

02The eight tasks

Alias store

Key normalisation (case and separator tolerant), atomic write via temp file plus rename, corrupt and missing files loading as empty, blank names removing the entry rather than storing a blank. Persistence only, no consumers yet. 9 tests.

+ alias.rslib.rs
3

Name resolution and collisions

Pure function over a slice: alias wins, else Claude's name, else the last path segment. Duplicates get #1 / #2 ordered by start time, ties broken on session id so numbering cannot flip between polls. 7 tests.

alias.rsmodel.rs
4

Reap ended sessions

Stamp ended_at on first sighting, carry it forward rather than restamping, drop the row after 10s. Carrying is what keeps the poller from spinning on a change that is really no change. 6 tests.

+ reap.rslib.rs
5

Wire into the poller, expose commands

Everything above is inert until the scan loop calls it. scan_once_with takes an injected alias map so it is testable; the integration test writes a fixture session file using the test process's own pid so it reads as alive. Adds set_alias and get_aliases.

poller.rsmain.rs
6

Overlay roster component

One row per session, sorted waiting then idle then working, muted "no sessions" empty state, window height following the row count and clamped before it can fill the screen. Deletes OverlayPill.tsx. 4 tests.

+ OverlayRoster.tsx+ OverlayRoster.test.tsxoverlay.tsxtypes.ts
7

Inline rename

Double click to edit, Enter commits, Escape cancels, blur commits, empty clears. The drag region moves off the container onto a dedicated grab strip, because a drag region swallows mouse events on Windows and would eat the double click. 5 tests.

Shown once at startup, never hidden. Position saved on move and restored before show, so there is no visible jump. focus: false so it never steals focus. Then the manual checklist below.

03Order and why

StageTasksReasoning
Standalone win1Independent of everything else and fixes a live irritation on its own. Worth having even if the rest slipped.
Pure logic2, 3, 4No app, no window, no filesystem beyond a temp dir. Fully covered by fast unit tests before anything is wired.
Integration5The single point where the pure pieces meet the running loop. If something breaks, it broke here.
UI6, 7Display before interaction, so a failing rename test cannot be confused with a failing render.
Window behaviour8Last because it is the only part that cannot be asserted, and it needs everything else working to be judged.

04Manual checklist (Task 8)

This is the acceptance criterion for the whole plan. v1 shipped without this pass, and that is why we are here. Anything that fails gets fixed before the commit, not filed as follow up.

  • Overlay appears at startup with nothing needing attention
  • Lists live sessions by name, one row each
  • A new Claude session adds a row within about 2 seconds
  • A session going idle turns its dot amber, and the overlay does not move or hide
  • Toast and tray icon colour still fire as they did in v1
  • Double click lets you type, Enter saves, and the name survives a restart
  • Two live sessions in one folder show name #1 and name #2
  • Dragging the top strip moves it; after a restart it reappears where you left it
  • Does not appear in alt tab, does not appear in the taskbar
  • Clicking it does not pull focus from a focused terminal
  • Height matches the row count from one to five rows, then scrolls rather than growing past ~420px
  • With no sessions it shows "no sessions" and stays visible
  • Ending a session leaves a grey row that disappears about 10 seconds later
Before running the dev build, kill the installed v1: it is currently running, and tauri_plugin_single_instance will refuse a second copy. Stop-Process -Name homa -Force
